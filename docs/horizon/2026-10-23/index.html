Quad9 因法院裁罚退出法国市场 ⭐️ 8.0/10

公共 DNS 解析器 Quad9 宣布将退出法国市场。此前法国法院认定其未遵守内容屏蔽命令构成藐视法庭并处以罚款：原告索尼音乐在德国通过 VPN 访问被地理封锁的内容，法院据此认定 Quad9 未合规。Quad9 CTO John Todd 在评论中表示，公司可能在 11 月 24 日之后用 geoIP 过滤阻止法国用户使用其服务，同时承认这与 Quad9 一贯主张“geoIP 封锁不足以按域名选择性拒绝解析”的立场存在冲突。

hackernews · farrokhi · 10月22日 14:32 · 社区讨论

「背景」 法国法院此前已要求 Google、Cloudflare 和 Cisco 等公共 DNS 解析器执行网站屏蔽令，这些公司均反对但未获成功，Google 和 Cloudflare 随后被迫实施屏蔽。Quad9 此次退出是在同一类法律压力下发生的，其 CTO 在评论中表示，公司可能在 11 月 24 日之后用 geoIP 过滤阻止法国用户访问其服务。

「影响」 对法国用户而言，Quad9 退出意味着少了一个可用的公共解析器选项，需转向其他 DNS 服务。对 DNS 运营方而言，此案显示即便屏蔽对象通过 VPN 绕过地理封锁，法院仍可能把未完全阻断的责任归于解析器并处以藐视法庭罚款，从而提高了在法国提供解析服务的法律风险。

「社区讨论」 有评论者认为，原告自己用 VPN 绕过封锁后却让解析器承担藐视法庭责任并不合理，并以“电话簿公司是否该为收录罪犯号码受罚”作类比。另有评论指出 Quad9 的退出与 Cisco 约两年前退出法国市场的做法相似，并提到 Canal+ 曾就体育盗播对 Google、Cloudflare 和 Cisco 的 DNS 解析器申请网页屏蔽令。

VeloCloud Orchestrator 曝 CVSS 9.9 SQL 注入漏洞，Arista 确认遭利用 ⭐️ 8.0/10

VeloCloud Orchestrator 中被发现一个 SQL 注入漏洞，编号 CVE-2026-114625，CVSS 评分为 9.9。攻击者可利用该漏洞从仅具只读权限的最低权限账户提升至对整个管理平台的完全控制。Arista 已确认该漏洞在真实环境中遭到利用。

rss · 情报の灯台 / Joho no Todai · 10月23日 12:21

「背景」 VeloCloud Orchestrator 是 VeloCloud SD-WAN 的集中管理组件，用于配置和监控分布在私有网络与互联网宽带上的企业站点。Arista 收购 VeloCloud 后，将其云交付 SD-WAN 资源整合到自家支持体系中。此次漏洞正是出现在这一管理平面上，使低权限账户可借 SQL 注入提升至对整个管理基盘的掌控。

「影响与应对」 该漏洞影响运行 VeloCloud Orchestrator 的企业 SD-WAN 基础设施运营方：一旦被利用，攻击者可从只读账户获得管理平台的全权控制。鉴于 Arista 已确认存在实际利用，相关运营方应优先排查只读账户的使用情况并尽快采取修补或缓解措施。

PHP2Shell 漏洞利用绕过 ASLR，生产环境亦可远程执行代码 ⭐️ 8.0/10

VulnCheck 声称已开发出针对 PHP2Shell 漏洞的利用程序，能够绕过 ASLR，并在 PHP 推荐的生产配置下实现远程代码执行。该消息来自一篇简短报道，未给出漏洞编号、受影响 PHP 版本、利用细节或独立复现结果，因此目前应视为厂商声明而非已获独立验证的能力。报道称，打补丁是唯一完整的防御手段。

rss · 情报の灯台 / Joho no Todai · 10月23日 10:53

「背景」 ASLR（地址空间布局随机化）通过随机化内存布局来提高漏洞利用难度，是生产环境常见的通用防护手段。此次报道称 VulnCheck 的利用代码在 PHP 推荐的本番设定下仍能绕过该防护并实现远程代码执行，但来源未给出技术细节或独立验证。

「影响」 若该利用程序确实有效，运行受影响 PHP 版本且无法及时升级的运维方将面临实际远程代码执行风险，仅靠 ASLR 等运行时缓解措施不足以阻断攻击。在补丁和受影响版本信息明确前，相关团队应优先确认自身 PHP 版本是否受影响，并准备升级方案。

vLLM 为 MiniMax-M3.1-Flash 提供首日支持 ⭐️ 7.0/10

rss · vLLM Blog · 10月23日 00:00

「背景」 MiniMax-M3.1-Flash 是 MiniMax-M3 系列的新模型，原生采用 NVFP4 KV 缓存和 NVFP4 量化的 MoE 权重，并配有 DSpark 草稿模型用于投机解码。vLLM 团队需要在发布当天于 NVIDIA Blackwell、Rubin 和 AMD MI350 系列 GPU 上提供支持，同时让稀疏注意力在长上下文解码中真正发挥带宽优势。

「方案」 作者的核心洞察是：MiniMax 稀疏注意力（MSA）把 KV 缓存按 128 token 分块，索引器用每个 GQA 组一个查询对共享索引键打分并池化为块分数，主注意力只精确计算 top-16 块，从而把每步 HBM 流量压到稠密注意力的约 12.5%。围绕这一机制，vLLM 在 Blackwell 上用 CUDA 13.4 的 QMUL4 指令在核内把 NVFP4 反量化为 FP8，索引器 QK 解码最高快 1.7 倍、稀疏注意力解码快 1.3 倍；NVFP4 MegaMoE 融合 MXFP8 共享专家并提前释放 TMEM，预填充核延迟降 20%、吞吐升 7%；索引器解码上下文并行（DCP）按上下文切分工作并经 NVLink 精确合并 top-16，512K 上下文下每稀疏层快 3.3 倍；QKV GEMM、norm、RoPE 与 KV 插入融合为单核，避免 QKV 张量往返 HBM，P50 TTFT 降约 19%。在 Rubin 上，索引器改为 NVFP4 直接转 FP16 做分数 MMA，减少约三分之一反量化指令且分数精确；AMD 侧则用 2 KB LDS 查表完成 NVFP4 到 FP8 转换，稀疏解码注意力比先转 FP8 再算快 2.5 倍，并用单次 1.82 MB 连续块传输替代 125 个小页 RDMA 读。作者报告 GB300 上延迟敏感端每用户 418.9 tok/s，Rubin 上 724.9 tok/s、每 GPU 191.5K tok/s，MI355X 上每美元 TCO 133.3M token；这些数字均为实现方自报，未附独立验证。

「启示」 作者认为，稀疏注意力的收益不只来自算法选择，更来自围绕 NVFP4 缓存、核融合和上下文并行做端到端带宽与启动开销优化；这些思路可迁移到其他长上下文推理场景。
