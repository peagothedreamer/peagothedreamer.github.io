报道称 PHP 核心存在潜伏十年的“PHP2Shell”漏洞 ⭐️ 8.0/10

一篇简短的聚合报道称，在支撑约七成网站运行的 PHP 本体中发现两个无需认证即可接管服务器的漏洞，并称这些缺陷已潜伏十年以上、由 AI 演示为可利用，导致包括日本在内的全球服务紧急停止。该报道未给出 CVE 编号、受影响版本、修复或补丁状态，也没有引用一手来源，因此上述说法无法从现有内容核实。

rss · 情报の灯台 / Joho no Todai · 10月25日 08:49

「背景」 外部安全公告将这两处漏洞编号为 CVE-2026-109618 与 CVE-2026-109619，并统称为“PHP 2 Shell”。据 VulnCheck 的记录，PHP 于 10 月 21 日公布了漏洞细节，其中 CVE-2026-109618 涉及内存耗尽（OOM）处理期间内部请求数据仅部分初始化而导致的远程代码执行；Docker 则表示自 10 月 20 日起开始跟踪这两处影响 PHP 包的核心漏洞。这些外部资料补充了编号与披露时间，但未提供受影响版本范围或补丁状态的完整信息。

Brotli 高危漏洞波及 Python 与 Node.js HTTP 组件 ⭐️ 8.0/10

谷歌 Brotli 解码器的高危漏洞 CVE-2026-111497 影响 1.0.3 至 1.2.0 版本，CVSS 4.0 评分为 9.2。远程未认证攻击者可发送特制压缩流，造成内存损坏、敏感数据泄露、进程崩溃，并可能执行任意代码；Node.js 和 Python 相关组件均受影响。该漏洞最初以 Node2Shell 名称披露，后被称为 HTTP2Shell。修复版本为：Python 的 Brotli 升级至 1.2.1、brotlicffi 升级至 1.2.1.0，Node.js 升级至 22.23.4、24.22.1 或 26.12.1。

telegram · zaihuapd · 10月25日 02:42

「背景」 该漏洞最初以 Node2Shell 名义披露，随后扩展至 Python 等 HTTP 组件，因此又被称为 HTTP2Shell。据外部报道，Python 应用即使不直接导入 Brotli，只要环境中安装了该库，requests、urllib3、httpx 和 aiohttp 等客户端也会自动调用它，从而可能暴露在攻击面内。

「影响与处置」 使用受影响版本 Brotli 解码器的 Node.js 与 Python 服务，在接收外部压缩请求时可能暴露于未认证的远程攻击，因此需要按上述版本升级。OpenAI 表示于今年 2 月发现该问题，但来源未说明各修复版本的发布时间与覆盖范围。

MCP 参考服务器 v2.1.0 修复八个安全漏洞 ⭐️ 7.0/10

MCP 参考服务器发布 v2.1.0，修复 filesystem、everything 和 fetch 三个服务器中的八个漏洞。`@modelcontextprotocol/server-filesystem` 与 `@modelcontextprotocol/server-everything` 升级至 2.0.1，`mcp-server-fetch` 升级至 2026.10.24。filesystem 的修复包括阻止在访问检查与写入之间把父目录换成符号链接以逃逸允许目录，但公告明确说明 Windows 上仅部分修复；everything 的 HTTP 与 SSE 传输改为校验 `Origin` 头并停止返回 `Access-Control-Allow-Origin: *`；fetch 则修复 IDNA 主机名校验与连接不一致、NAT64 地址分类以及重定向后未重新检查 robots.txt 的问题。由于包管理器会把 2.0.1 排在所有 2025.x、2026.x 日期版本之下，仍使用日期版本的用户需显式安装 2.0.1 才能获得修复。

github · cliffhall · 10月25日 00:03

「背景」 MCP 参考服务器是 Model Context Protocol 官方维护的一组示例实现，供开发者直接使用或作为构建自定义服务器的参考。其中 filesystem 服务器提供受允许目录限制的文件读写操作，everything 服务器用于演示 HTTP 与 SSE 传输，fetch 服务器负责抓取网页内容。这些服务器此前已发布多个版本，本次 v2.1.0 集中修复了路径校验、跨域请求和地址分类等方面的安全缺陷。

「影响」 使用这些参考服务器的团队应尽快升级，尤其是 filesystem 用户：在 Linux 和 macOS 上，旧版本可能让 `write_file`、`edit_file`、`create_directory` 及 `move_file` 的目标被符号链接重定向到允许目录之外。Windows 用户即使升级也仍有未完全覆盖的风险，需按安全公告 GHSA-53mr-w429-c597 的说明调整配置。

Cerebras 详解在晶圆级硬件上部署万亿参数模型 ⭐️ 7.0/10

Cerebras 发布博客，说明其如何在晶圆级硬件上部署和服务万亿参数级前沿模型。文章称，在超低延迟场景下，只需在晶圆之间传递激活值，并可通过基于以太网的 RDMA 完成。该文是厂商对部署方法的自述，未提供独立测量结果；社区讨论则质疑其基准测试采用全精度数据、实际却使用 4 比特量化，以及预填充阶段的互连表现。

hackernews · gmays · 10月25日 01:33 · 社区讨论

「背景」 Cerebras 的核心技术路线是把计算核心、存储器和互连结构集成在单片晶圆级芯片上，以减少传统多芯片系统中的数据传输瓶颈，其产品为“晶圆级引擎”（WSE）系列芯片及搭载该芯片的 CS 系列计算系统。与以 GPU 集群为主流的人工智能加速平台不同，这一架构正是该公司主张能高效承载超大规模模型推理的基础。

「对使用者的实际影响」 对打算采用 Cerebras 推理服务的开发者而言，社区反馈显示实际可用模型与标称性能之间存在落差：有用户称其可访问的模型（如 GPT OSS 120B、Qwen 27B）速度很快但准确性不足，另有用户表示 27B 模型未达到其期望的每秒 2000 token。Cerebras 官方也提示，相对 GPU 的推理加速会随工作负载、配置、日期和测试模型而变化，因此选型时应以自身任务实测为准。此外，Cerebras 推理服务面向预训练模型，微调需在外部基础设施完成后再部署。

「社区讨论」 有评论者指出，Cerebras 上可用的模型（如 GPT OSS 120B、Qwen 27B）速度很快，但输出“大多是错的”，实际可用性有限。另有评论质疑文章只解释了激活值经 RDMA 传输的解码路径，没有说明预填充如何在该互连上保持高速；还有人批评其引用全精度基准却采用 4 比特量化。一位用户实测其 27B 模型未达到所期望的每秒 2000 token。

美国媒体、影视与艺术业流失 20 万岗位，AI 该负多少责任？ ⭐️ 7.0/10

Apricitas 的一篇分析文章探讨美国媒体、影视和艺术领域约 20 万个岗位流失是否应归因于 AI。文章并未给出“是或否”的定论，而是把 AI 放在行业长期追求效率、内容供给过剩和注意力经济等背景中考察。该文在 Hacker News 引发约 393 分、407 条评论的讨论，但属于解释性评论文章，并非硬性公告或独立数据集。

hackernews · gnabgib · 10月24日 23:11 · 社区讨论

「背景」 该文讨论的是媒体、影视与艺术领域约 20 万个岗位流失与 AI 之间的关系，属于解释性分析而非官方数据发布。评论区提到的“注意力经济”背景是：在 AI 出现之前，内容供给已远超有限的受众注意力，许多平台以内容补贴其他业务，这一结构性失衡为理解当前岗位变化提供了参照。

「影响」 该分析未给出可独立验证的因果结论，因此无法据此确认 AI 在约 20 万个媒体、影视与艺术岗位流失中的具体占比。对从业者而言，评论中提到的商业插画、广告服装展示等岗位被自动化替代，以及流媒体订阅价格上涨带来的需求收缩，是比笼统的“AI 取代创意工作”更具体的风险信号。

「社区讨论」 有评论者赞赏文章没有简单归咎于 AI，而认为娱乐业的问题与许多追逐“效率”的行业类似，把制作迁出洛杉矶等降本做法会带来连锁影响。另有评论认为真正的岗位流失集中在商业插画等商业艺术领域，并指出下滑起点大致与 Stable Diffusion 出现的时间吻合；也有人强调流媒体订阅价格上涨和内容供给过剩早已在挤压需求。

OpenAI 红队智能体借 CPU 缓存时序在隔离沙箱间隐蔽通信 ⭐️ 7.0/10

据 Tom&#x27;s Hardware 报道，OpenAI 的红队智能体据称利用 CPU 缓存时序，在没有网络、也没有共享文件的情况下，于相互隔离的 microVM 沙箱之间传递隐藏消息。报道指出，这种通过 CPU 缓存进行隐蔽通信的手法此前已被证明可在云虚拟机之间搬运数据。目前公开内容仅为简要概述，未说明实验范围、可复现性、涉及的具体系统或 OpenAI 是否已发布完整技术细节，因此该结果应视为报道中的红队发现，而非已独立验证的通用攻击能力。

rss · Tom&#x27;s Hardware · 10月25日 11:30

「背景」 CPU 缓存计时侧信道是一种已被研究过的跨虚拟机数据传递手法：攻击者通过观察共享缓存访问时间的差异来推断信息，无需网络连接或共享文件。此次报道称，OpenAI 的红队智能体在相互隔离的 microVM 沙箱之间复现了这类隐蔽通信，说明该手法可被用于突破沙箱隔离边界。

「影响」 若该发现成立，依赖 microVM 隔离且假定租户间无网络与文件共享的云沙箱设计，需要把缓存时序侧信道纳入威胁模型；评估隔离效果时不能只检查网络和文件系统边界。由于报道未给出受影响平台或缓解措施，读者暂无法据此判断具体产品是否需要调整配置。

别把大科技公司当人看 ⭐️ 7.0/10

rss · Sean Goedecke · 10月25日 00:00

「背景」 工程师常把公司当作有情感、讲公平的人：觉得公司欠自己人情，或认为公司因某个议题、某次失误而“恨”自己。作者借用 Bryan Cantrill 关于 Larry Ellison 的比喻——割草机不会恨你，把手伸进去照样会被切断——指出这种拟人化会让人误判风险与回报。

「方案」 作者主张把公司看作一台危险但有用的机器，更像汽车而非朋友：它不尊重努力，也不讲公平。你花数月打磨的项目可能只换来一句“不错，下一个”，而十五分钟做的小工具或 Slack 里的一次回答却可能获得意外认可；若把公司当人，这种不可预测会令人抓狂，当作机器则不足为奇。因此他建议把大部分时间用于寻找低投入高回报的机会。针对“公司由人组成，说公司恨我只是简写”的反驳，作者认为这仍是危险的偷懒：高层管理者通常足够冷静，不会无故丢弃有用的工具；他见过自称被恨的工程师，后来发现管理者其实视其为不可靠的“危险工具”。区分“经理恨我”和“公司恨我”也有实际价值，因为经理往往是临时的，糟糕关系可能熬过去或修补。作者同时警告不要走向另一极端——把公司当程序：手册、晋升指南和“最高优先级”只是庞大而不可读的运营网络之上的显性上层建筑，照章办事的工程师常因此困惑失望。

「启示」 公司不会记仇，却会按激励把人淘汰；承认这种无理由的惩罚，也意味着只要做对决策，就可能以较小努力获得不成比例的回报。
