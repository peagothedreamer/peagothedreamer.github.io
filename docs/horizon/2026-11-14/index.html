TorchTitan 在 384 块 GH200 上训练约 1T 参数 MoE ⭐️ 7.0/10

一位实践者报告称，团队借助 TorchTitan 在 384 块 GH200 GPU 上训练约 1T 参数的 MoE 模型，达到每 GPU 约 1,300 tokens/s，是起始点的 14 倍。方案采用 384 路 FSDP 加 4 路专家并行（EP 严格限制在节点内），并跳过流水线并行以缩短迭代周期。关键优化包括全量激活检查点、将检查点激活卸载到 Grace 并通过 C2C 链路预取、用 Muon 替代 Adam 以支持 64k token 序列，以及把 Newton-Schulz 迭代放到 GPU 上执行，使优化器步从 42 秒降至约 2 秒、吞吐提升 35%。这些数字来自作者自述的实测，而非独立复现。

reddit · r/MachineLearning · /u/f14-bertolotti · 11月13日 16:28

「背景」 TorchTitan 是 PyTorch 原生的开源大规模训练框架，其设计目标是在同一套代码中组合 FSDP、张量并行、流水线并行、上下文并行与专家并行，并集成 Float8、激活检查点等内存优化手段。该文作者正是基于这一框架，在 JUPITER 超算的 GH200 集群上尝试把约 1T 参数的 MoE 训练推到更高吞吐。

「对大规模训练团队的意义」 作者称，一台公共资助的 Hopper 代际机器在普通用户权限、无 root 的条件下即可承载前沿规模训练，但受限于节点间带宽：JUPITER 上 InfiniBand 每 GPU 约 25 GB/s，比 NVLink 慢 6 倍。文中多项改动已进入或正在进入 TorchTitan/PyTorch：FlexShard 已在 TorchTitan 中，GPU 端 Newton-Schulz 修复已贡献，FSDP2 的 unshard_async_op 私有标志正转为公开 API，相关团队可据此评估升级。

NVIDIA cuPhoton.xBeam：GPU 加速黑洞干涉测量 ⭐️ 7.0/10

rss · NVIDIA CUDA Technical Blog · 11月13日 21:17

「背景」 事件视界望远镜（EHT）通过甚长基线干涉测量（VLBI）将全球多台射电望远镜同步记录的高速电压流关联起来，以重建黑洞图像；下一代 EHT 计划增加站点，数据量将达 PB 级，传统 CPU 相关器成为瓶颈。

「方案」 作者详细介绍了 NVIDIA cuPhoton.xBeam 这一 GPU FX 相关器：它先为 VDIF 记录建立 .vdix 索引以便并行读取，再在 GPU 上依次完成延迟与条纹校正、FFT 信道化、台站对交叉相乘与积分，最后输出 DiFX SWIN 或 xbeam-v1 格式的可见度。延迟模型来自作业文件中的几何延迟多项式、钟差和频段固定偏移，fringe_approximation_order 控制 FFT 内延迟的 0/1/2 阶近似；xBeam 本身不计算延迟，也不追踪黑洞附近光路。数据可通过 POSIX 固定主机内存或 cuFile/GPUDirect Storage 进入 GPU，多 GPU 按时间分片（–shard-count/–shard-index），merge-shards 在校验作业一致性和时间覆盖后合并结果。作者报告在 Vera Rubin NVL72 的 64 GPU 上，10 TB 数据端到端处理耗时 70 秒，约为 x86 CPU 基线 31,992 秒的 460 倍；读取带宽从 4 GPU 的 20 GB/s 增至 64 GPU 的 170 GB/s。这些是厂商在特定系统上的基准，方法细节有限；下游校准与成像不在教程范围内，AI 代理部分属于展望。

「启示」 作者认为，将相关器的延迟校正、FFT 和交叉相乘全部放到 GPU 上，并按时间分片扩展，能显著缩短 VLBI 海量数据的处理时间，为 ngEHT 等下一代观测提供可行的数据管道基础。
