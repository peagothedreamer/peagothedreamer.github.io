最高法院裁定特朗普大部分关税无效 ⭐️ 9.0/10

据 ABC 新闻报道，美国最高法院裁定特朗普政府的大部分关税无效。该报道未提供裁决的具体范围、法律依据或生效时间，因此实际关税削减幅度尚无法核实。

google_news · ABC News - Breaking News, Latest News and Videos · 10月19日 06:25

「背景」 据 ABC 新闻报道，最高法院此次裁决推翻了特朗普全球关税的约 70%；截至去年 12 月，这些关税已征收超过 1420 亿美元（耶鲁预算实验室数据）。法院认定，《国际紧急经济权力法》（IEEPA）并未授权总统单方面征收范围、期限和金额均不受限制的关税，此类广泛权力需要国会明确授权。

「市场影响」 若裁决确实使大部分关税失效，进口成本将下降，直接利好依赖进口商品和金属原料的美国零售商、汽车制造商与制造业企业；同时可能压低商品通胀，从而影响美联储利率路径和股市估值。但报道未说明裁决范围与生效时间，实际关税降幅无法核实。

google_news · Morningstar · 10月19日 19:43

「背景」 美国劳工统计局数据显示，9 月 CPI 同比上涨 3.7%，高于 8 月的 3.4%，环比上涨 0.6%；核心 CPI 剔除食品和能源，具体数值未在现有材料中给出。这是美联储本月晚些时候议息会议前最后一批通胀数据之一。

「对市场的影响」 据外部报道，9 月 CPI 加速上行，强化了市场对美联储可能进一步加息的预期（tool-2-1、tool-2-3）。若加息预期升温，美国国债收益率可能上行，进而压低股票估值，尤其是对利率敏感的成长股和长久期资产；房贷、车贷等与基准利率挂钩的借贷成本也可能维持高位，影响美国家庭和企业的融资负担。

美国国土安全部下令将 DeepSeek 产品排除出联邦文职采购 ⭐️ 8.0/10

美国国土安全部发布命令通知，依据《联邦采购供应链安全法》，将杭州深度求索人工智能基础技术研究有限公司（DeepSeek）及其关联实体开发的信息技术产品与服务排除出联邦文职行政部门的采购范围。命令同时要求从文职机构信息系统中移除所有 DeepSeek 及相关实体产品，以及使用 DeepSeek 实现的第三方产品与服务。该命令涵盖 DeepSeek 及其关联方，并延伸至基于其实现的第三方产品；此前国防部与情报界已对 DeepSeek 有类似使用限制。

telegram · zaihuapd · 10月19日 13:32

「背景」 该命令依据《2018 年联邦采购供应链安全法》（41 U.S.C. §§ 1321-1328）及其在 41 C.F.R. part 201-1 的实施条例发布，授权国土安全部部长为保护联邦文职信息系统而签发排除或移除令。据来源摘要，国防部与情报界此前已对 DeepSeek 设有类似使用限制，此次将限制范围扩展至联邦文职行政部门。

「影响」 命令将限制范围从国防与情报领域扩大到联邦文职机构，涉及采购准入与存量系统清理两个环节。为联邦文职机构提供 IT 服务的集成商需排查其产品是否基于 DeepSeek 实现，因为命令明确覆盖此类第三方产品与服务。

安全报告称单一黑客用 AI 代理攻击逾 1200 家电商网站 ⭐️ 8.0/10

网络安全公司 NorForge 的研究员 Snorre Fagerland 在 10 月 19 日（周一）发布的报告中称，一名讲中文的攻击者几乎完全把攻击委托给自主运行的 AI 代理，这些代理可连续工作数小时。据路透社在发布前看到的报告，该行动自 9 月 25 日起针对美国、加拿大、澳大利亚和日本的电商网站，尝试入侵超过 1200 个站点，平均每次成功入侵耗时约 23 小时，总成本约 5000 美元，即每次约 50 美元。报告称攻击通过名为 Cairn 的开源平台协调，可能运行了 Claude Code 搭配 DeepSeek V4.1 Flash 模型，指令不足 100 个汉字，目标是植入隐蔽的 web shell 以获取对商店和支付系统的持久访问。上述内容均来自单一厂商报告，经社交媒体账号转述，模型归属和报告细节尚未获得独立验证。

twitter · Glitch News · 10月19日 20:53

「背景」 该报道由安全公司 NorForge 的研究员 Snorre Fagerland 发布，路透社在发布前已查阅报告。报告称攻击者通过开源编排平台 Cairn 调度 AI 代理，并可能使用 Claude Code 搭配 DeepSeek V4.1 Flash 模型，以不足 100 个汉字的指令驱动攻击。这些归因与工具细节目前仅来自单一厂商报告，尚未获得独立验证。

「影响与应对」 被点名的企业中，Deere 表示没有迹象显示敏感数据被访问，SharkNinja 称攻击涉及一个独立的支持网站且已被控制，Cummins 表示正在调查。若报告属实，约 50 美元的单次入侵成本意味着中小型电商面临的经济门槛显著降低，运营方应重点排查 web shell 等持久化后门，并审查支付系统的访问日志。

vLLM Elastic EP 将扩缩容停机降至近零 ⭐️ 8.0/10

rss · vLLM Blog · 10月19日 00:00

「背景」 大模型推理服务扩容时，传统做法是增加整个副本或重启引擎，而模型越大每个副本占用的 GPU 越多，扩缩容的粒度也随之变粗。作者指出，把 DeepSeek V4 Pro 从 16 张 GB200 重启扩到 20 张时，服务中断达 197 秒；此前 Elastic EP 虽能在线增删 GPU，但重配置期间仍需初始化新 worker、准备通信组、加载权重并重新捕获 CUDA graph，停机约 100 秒。

「方案」 作者把重配置拆成后台准备与短暂提交两个阶段：现有 worker 用后台线程准备目标通信、传输权重并与新 worker 同步执行信息，同时继续用旧通信组和 CUDA graph 服务请求；提交阶段只短暂暂停调度器，激活已准备好的拓扑。关键机制是 NIXL EP——它原地增删 rank，复用同一 agent、缓冲区和连接，新 peer 在准备期连接但不激活，提交时直接启用，因此保留 worker 的 CUDA graph 不会失效。为满足 CUDA graph 对指针、启动配置和张量地址稳定的要求，vLLM 还复用了 fused-MoE 执行对象，保持工作区与 dispatch 输出地址布局不变，并原地更新专家路由张量映射。新加入的 worker 则在预热时屏蔽所有远端 EP peer、不等待 DP 批次信息，独立完成图捕获后再激活 peer。在 DeepSeek V4 Pro 基准中，停机从阻塞式的 99.62 秒降至 0.82 秒（16→20），缩容从 56.25 秒降至 1.96 秒；总耗时扩缩容分别为 92.34 秒和 9.32 秒，说明准备时间仍不可忽略。11,391 请求的 SLO 回放中，Elastic EP 全程保持 p95 TTFT 低于 5 秒，准备期与静态 16 GPU 部署持平，扩容后与 20 GPU 部署持平。

「启示」 作者的核心结论是：把拓扑准备与提交分离、并让通信器原地扩展以保住 CUDA graph，就能把扩缩容停机从分钟级压到秒级，使弹性 EP 在真实负载下接近静态部署的表现。剩余成本主要在总准备时间，以及 NIXL EP 尚未达到最优 dispatch 性能。

识别可放弃的需求，才是优雅系统设计的关键 ⭐️ 8.0/10

rss · Sean Goedecke · 10月19日 00:00

「背景」 软件设计常被理解为满足尽可能多的需求，但作者认为，明确哪些需求可以放弃——哪些可以慢、可以陈旧、可以不灵活——往往才是优雅设计的前提。

「方案」 作者用多个系统说明这一思路：Unicorn 不处理慢客户端，因此能把请求直接排在 Unix socket 上；S3 不支持多键原子更新，反而能按 blob 独立存储，减少跨分区协调；StatsD 默认用 UDP，放弃“每条数据必达”，换来更低网络开销；边缘缓存和 SQLite 也分别以数据可能陈旧、放弃并发写为代价，换取速度与单文件运行的简单性。作者指出，难点在于同时判断技术代价和业务可接受度，而工程师与产品经理之间缺乏信任时，往往没人敢先让步；单人开发者或初创公司有时反而因技术与业务决策合一而占优。在 LLM 编码代理场景中，模型会因追求“正确”而自行引入互斥锁、重复检查等假设性需求，把四行改动膨胀成千行；作者建议在提示中明确可接受陈旧数据，并在审查 Go 代码时优先扫描不必要的锁和间接层。

「启示」 优雅系统来自对需求的刻意取舍，而非全部满足；在 AI 辅助编码时代，识别并阻止模型自行添加的假设性需求，是保持系统可扩展的关键审查动作。

用 cuTile 在 Python 中实现 Mamba-2 前向核 ⭐️ 7.0/10

rss · NVIDIA CUDA Technical Blog · 10月19日 17:00

「背景」 序列建模长期面临两难：softmax 注意力训练时能充分利用 Tensor Core 做矩阵乘，但推理的算力与显存随序列长度线性增长；RNN 推理时算力恒定、显存固定，却难以并行训练。Mamba-2 试图兼得两者，其核心是固定尺寸的矩阵隐状态与逐 token 的递推更新，但训练和 prefill 阶段不能真的用 for 循环串行执行。

「方案」 作者（Jane Street 的工程师与 NVIDIA 合作）把递推按 chunk 展开：忽略衰减项时，从 h_t 跳到 h_{t+T} 只是把一块 b 与 x 堆成矩阵后做 BX^T，输出则化为 Y = Ch_t + ((CB^T)·M)X + DX，其中 M 是因果掩码，形式上非常接近无 softmax 的线性注意力。加入衰减 exp(a_t) 后，作者在 log 空间用累积和 G 替代连乘，得到 h_{t+T} = exp(G_last)h_t + (exp(G_last−G)·B)X^T，以及输出式中的 exp(G−G^T) 逐对衰减；由于所有 a_t 为负，被掩码保留的项指数必为负，数值稳定。据此拆成三个核：chunk_cumsum 用 ct.cumsum 算块内累积和并乘 log2(e) 以便用 exp2；fwd_pass_state 在单个 grid 点内顺序遍历 chunk，用 ct.mma 推进隐状态，并把最终状态存下供推理续用；compute_out 把 C@B^T 交互矩阵留在寄存器中，分两阶段融合携带状态项、逐对衰减、因果掩码与 D·x 残差。优化上，作者用 latency hint 指导流水调度，在 Blackwell 上利用 B^T A^T=(AB)^T 把融合操作数换到 A 操作数以缓解共享内存压力，把 decay_cumsum 与 dt 转置为 [batch, head, token] 布局以启用 TMA，并用 cuTile 自动调优器按输入形状搜索 block_size 与占用率。在单张 B300（Blackwell Ultra）上对比 Triton 参考实现（mamba_ssm 2.3.2、Triton 3.7.1），核级加速为 1.14x–1.82x，且随序列长度与 state size 增大而提升；作者明确这仅是核级数据，端到端训练还取决于反向传播。

「启示」 作者的结论是：把 Mamba-2 的 chunked 递推改写成 log 空间累积和加因果矩阵乘后，用 cuTile 的 tile 级 Python DSL 就能写出贴近硬件的核，并在 Blackwell 上稳定快于 Triton 参考实现。其更大意义在于，这类张量核心友好的改写与布局、操作数调度技巧，可迁移到其他带衰减的线性注意力式模型。
