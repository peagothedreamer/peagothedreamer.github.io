### [OpenAI 论困惑度与智能，引发评测方法争论](https://openai.com/index/perplexity-and-intelligence/) ⭐️ 7.0/10

OpenAI 发布文章《Perplexity and Intelligence》，主张更低的困惑度（即模型预测下一个 token 的交叉熵损失）与更强的模型智能相关，并给出一个简单的基准趋势。文章未在正文中定义困惑度，也未提供可核验的具体基准数值，因此其结论目前属于厂商论述而非独立测量结果。该文在 Hacker News 获得 615 分、406 条评论，讨论集中在交叉熵损失在强化学习时代是否仍然重要，以及简单基准是否优于日益复杂的评测。

hackernews · acossta · 11月22日 17:06 · [社区讨论](https://news.ycombinator.com/item?id=50601525)

**「背景」** 困惑度（perplexity）是语言模型预测下一个 token 时的平均不确定性度量：完全确定时取值为 1，随机猜测时约等于词表大小。OpenAI 这篇文章讨论的是，在跨实验室评测数据集和训练数据各不相同、难以直接比较的情况下，能否用这一预训练指标作为衡量模型能力的共同尺度。

**「对模型评估的影响」** 若这一关联成立，模型评估可能更依赖在固定留出集上测量下一词预测损失，而非不断叠加的复杂基准。评论者指出，微软已表示将把 MAI 模型加入同一评估集并公布预训练进展，这意味着跨厂商的困惑度对比可能成为可操作的公开指标；但该说法来自评论转述的推文，尚非独立验证。

**「社区讨论」** 有评论者补充了困惑度的定义：它衡量模型预测下一个 token 时的“意外程度”，最差情况等于词表大小，最好情况为 1。jrflo 表示，在强化学习日益普及后仍看到交叉熵损失与智能如此清晰的趋势“令人震惊”，并认为简单基准比层出不穷的复杂评测更有价值；d\_burfoot 则认为预测率即压缩率，本就是捕捉智能进展的恰当指标，并称自己 2008 年的论文已提出类似观点。reasonableklout 称微软的 Mustafa Suleyman 表示将以 OpenAI 的评测集报告 MAI-2 Base 的 log-perplexity 为 0.819，但该说法来自转述的推文，未经独立核实。

### [研究团队在 44 个开源项目中报告 112 处授权缺陷](https://joho-todai.com/oss-authorization-vulnerabilities-112-findings/) ⭐️ 7.0/10

北京邮电大学的研究团队分析了 57 个开源 Web 应用，报告在 44 个项目中发现了 112 处授权缺陷。其中 41 处源于权限检查对象错误，40 处则是完全缺少检查。该结果来自研究团队的论文报告，未在现有材料中列出具体项目名称、CVE 编号或修复建议。

**「对使用者的影响」** 由于报告未公开受影响项目清单和 CVE 编号，部署或维护这些开源 Web 应用的组织目前无法据此定位自身实例是否存在对应缺陷，只能等待后续披露或自行开展授权逻辑审计。

### [MoRI UMBP：把智能体 KV 缓存直接放到 NVMe](https://vllm.ai/blog/2026-11-23-skip-the-dram-tier) ⭐️ 8.0/10

rss · vLLM Blog · 11月23日 00:00

**「背景」** 智能体服务中，多轮会话反复重发长前缀：AgentX 回放里中位单轮输入达 142K token，其中 96% 以上是服务器已见过的前缀。KV 缓存命中率每提高 1 个百分点（如 95%→96%），作者在 Kimi-K3 的 42 次运行中测得约 10% 的吞吐提升；但 Kimi-K3 每小时向池写入 2.3–4.6 TB KV，1.8 TB 的 DRAM 池（标价约 7.6 万美元）只能保留最近 23–47 分钟，容量成为瓶颈。

**「方案」** 作者在 AMD MI355X 上用 MoRI 的 UMBP 池做了对照实验：同为 1.8 TB 的 DRAM 池与纯 NVMe 池，在 48/70/96 并发会话下吞吐差距在 1% 以内，并在另一对机器上复现（NVMe 反而领先 0.4%–0.9%）；KV 命中率相差不超过 0.08 个百分点，TTFT 中位数差距在 0.3–0.8 秒内。NVMe 池没有 DRAM 层，DRAM 只承担 64 GB 写缓冲和 16 GiB 读暂存，约占池容量 5%；作者认为关键在于同尺寸池淘汰策略相同、命中率相同，而 vLLM 异步加载让 NVMe 较慢的读取被 prefill 等待时间掩盖。三项工程改动带来实测收益：段文件从 4 GiB 缩到 256 MiB，使 70 会话吞吐提升 15.6%、TTFT p90 从 63.0 秒降到 21.3 秒；touch 上报 GPU 命中，使吞吐增加 2.1%–3.9%；混合模型每 7168 token 设检查点，使命中率从 91.4% 升至 95.6%、吞吐提升 33%。成本上，DRAM 按持有容量计价（约 4.2 万美元/TB），NVMe 按写入磨损计价（约 0.36 美元/TB 写入），因此 83 TB 写入/天的盘组可存一天 KV，五年约 5.9 万美元，而同等保留时间的 DRAM 池约 350 万美元。作者也坦承局限：96 会话下测试盘组约 5.5 个月耗尽额定寿命，成本是标价算术而非实测，且“一天保留换约 10% 吞吐”的估计串联了两个拟合模型。

**「启示」** 作者的核心论点是：当 KV 池容量而非介质延迟成为瓶颈时，跳过 DRAM 层、把智能体 KV 缓存直接放在 NVMe 上，可以在同等容量下保持吞吐，并用按写入计价的成本换取数量级更长的保留时间；代价是 SSD 磨损，需要靠分布式池分摊写入。

### [不确定时，不妨“乱试一通”](https://seangoedecke.com/when-in-doubt-flail-about/) ⭐️ 6.0/10

rss · Sean Goedecke · 11月23日 00:00

**「背景」** 面对产品方向不明、系统过于复杂或组织问题难以言说的局面，工程师常倾向于先谨慎分析、等看清全貌再行动。作者认为，在信息不足时这种等待往往代价更高，因为现代大型软件系统变化太快、太复杂，很难靠静态分析找到正确切入点。

**「方案」** 作者提出“有策略地乱试”：大量尝试不同做法，密切关注来自同事和现实指标的反馈，并果断放弃没有获得积极反馈的方案。多试不仅是为了接触更多现实，也因为多数初始想法本就不靠谱，且同时持有多个方案能避免过度投入。作者把这种策略对应到三类场景：产品尚未找到市场契合时，在边缘快速试错，他以自己在 GitHub Models 的经历为例，称“用 GitHub Actions token 运行 AI 推理”这一尝试意外成为“Continuous AI”的种子；工程系统难以入手时，先做一批推测性改动看效果，不行就立即放弃，AI 代理可帮助快速生成多个重构方案；组织问题中，主动尝试自动化、接手任务或提出长期计划，但此时最需要敏感于反馈，否则帮助对象的不满会转向自己。作者也承认，乱试不当会损害声誉，且从内部感受上像反复失败，但若及时放弃失败方案，这种不适可被当作积极信号。

**「启示」** 作者的核心论点是：在高度不确定的产品、工程和组织问题中，有反馈纪律的快速试错比谨慎分析更有效。其价值不在于“乱”，而在于用大量低成本尝试换取真实反馈，并随时准备放弃。

### [解读 OpenAI 困惑度曲线：预训练、RL 与安全透明度](https://seangoedecke.com/notes-on-openais-perplexity-reveal/) ⭐️ 5.0/10

**「背景」** OpenAI 罕见地公开了一张覆盖其所有已发布模型的困惑度随时间变化图，这是外界迄今对前沿实验室内部训练指标最深入的一次窥视。作者借此讨论困惑度究竟能衡量什么、模型谱系透露了哪些信息，以及这对安全透明度意味着什么。

**「方案」** 作者指出，困惑度只反映模型对特定留出文本的拟合程度，本质上只适用于预训练；而据传前沿模型一半以上的训练时间与算力花在 RL 上，这部分完全不在图中体现。若相信预训练创造能力、RL 只是将其引出，困惑度可视为能力的粗略代理，但它无法捕捉链式思考等不必然相关的维度。图中值得注意之处包括：极少模型共享同一基座，传闻中 4o 与 4.1 被反复后训练的说法不成立，实际只有 o1 和 o3 共享基座；4.1 与 o3 同源却表现悬殊；GPT-4.5 处可见 OpenAI 一度放弃扩大预训练模型，其困惑度接近 GPT-5.3-Codex 却远不实用；从 GPT-5.2 起困惑度损失明显加速，这与“实验室已放弃预训练、全力转向 RL”的流行说法相矛盾。作者还提醒，不同实验室的数据因依赖各自的留出数据集而难以直接比较，只能看曲线斜率；若安全界想据此设定阈值，必须公开数据集细节。

**「启示」** 作者认为，这张图既证明预训练仍在快速进步，也暴露了困惑度作为能力与安全指标的局限：它只覆盖训练的一部分，且缺乏数据集透明度就难以支撑跨实验室的监管约定。
