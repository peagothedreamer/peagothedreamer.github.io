### [cuDSS 1.0：稀疏直接求解器的精度与性能改进](https://developer.nvidia.com/blog/accelerating-direct-sparse-solvers-for-computational-engineering-with-nvidia-cudss-1-0/) ⭐️ 7.0/10

rss · NVIDIA CUDA Technical Blog · 11月23日 19:59

**「背景」** 工程仿真中的稀疏线性系统规模与精度要求不断上升，开发者需要能在 GPU 上扩展、同时保持生产级鲁棒性的直接求解器。NVIDIA cuDSS 1.0 正式版宣称在性能之外，重点改进了对称不定系统等困难问题的数值精度。

**「方案」** 作者给出的核心机制有两项：一是默认开启的保对称匹配与缩放（基于 HSL MC64），二是 Bunch-Kaufman 主元选择。此前匹配因破坏对称性而默认关闭，对角主元在小对角元场景（如鞍点、KKT 矩阵）会导致不可恢复的精度损失；Bunch-Kaufman 允许 2×2 主元，在保持对称性的同时稳定分解，并与匹配配合，使重排序把候选 1×1/2×2 组保持相邻。作者在 SuiteSparse 矩阵上对比了“无匹配+对角主元”与“匹配+Bunch-Kaufman”两种配置，后者在 kkt\_power、cont-300 等矩阵上把扰动主元数从数万降到 0，NRBE 最多改善约 10 个数量级；作者也坦承匹配加缩放并非总能提升精度，少数情况下反而变差，可通过 CUDSS\_MATCHING\_ALG\_NONE 关闭。性能方面，作者报告相对 Intel MKL 2026.1.0 的几何平均加速为分析 2.5 倍、数值分解 5.9 倍、三角求解 151 倍，但这是厂商基准，方法细节有限。此外，混合内存模式把 CPU DRAM 作为 GPU 显存的延伸，作者称大型 VLSI 用例的最低显存需求平均降低 30%，并新增可配置的 pinned memory handler 以减少注册开销。

**「启示」** 作者的核心论点是：稀疏直接求解器的进步不仅来自 GPU 算力，更来自保对称匹配与 Bunch-Kaufman 主元这类数值策略对鲁棒性的实质改善；对处理对称不定系统的开发者而言，这部分精度证据比厂商加速比更具参考价值。

### [Sirius：为 DuckDB 带来 GPU 加速的核心扩展](https://developer.nvidia.com/blog/get-started-with-gpu-accelerated-duckdb-analytics-using-the-sirius-core-extension/) ⭐️ 5.0/10

rss · NVIDIA CUDA Technical Blog · 11月23日 17:09

**「背景」** 随着数据集增长，DuckDB 上的分析查询会变慢，拖累数据探索与流水线响应。NVIDIA 与 DuckLabs 合作，将威斯康星大学麦迪逊分校与 NVIDIA 共同开发的开源 GPU 原生 SQL 引擎 Sirius 以 DuckDB 核心扩展形式发布，目标是在不改写 SQL、不改数据库模式的前提下加速受支持的查询。

**「方案」** 作者介绍，集成方式是分工而非替换：DuckDB 继续负责 SQL 解析与优化，Sirius 接收优化后的查询计划并在 NVIDIA GPU 上整体执行，结果仍通过同一连接返回；遇到不支持的特性则自动回退到 DuckDB 的 CPU 引擎。上手只需 INSTALL sirius; 与 LOAD sirius; 两条命令（扩展约 700 MB），前提是 DuckDB 2.0 和兼容驱动的 NVIDIA GPU。文中用 TPC-H 扩展生成 sf=0.01 的小数据集，执行一条按 l\_returnflag 分组求和的查询，并明确说明该示例只演示流程、不用于展示性能。作者随后给出厂商自测基准：数据存于 Amazon S3，覆盖 SF100 至 SF10K，使用固定开发版本；Sirius 计时不含结果导出，而 DuckDB 计时包含 CSV 输出，成本仅计实例运行时间。调优后的双 GPU 配置相对最佳 CPU 配置取得 3.25x 至 5.50x 加速，例如 SF1K 从 347.3 秒降至 63.2 秒，SF3K 从 752.4 秒降至 160.6 秒（4.69x，查询期计算成本约降 71%），SF10K 为 729.9 秒对 2,369.4 秒（3.25x，成本约降 79%）。结果还显示配置随规模变化：SF100 时单 GPU 成本最低、双 GPU 最快；SF10K 时默认双 GPU 配置“未完成”，调优后才跑完，说明调优在大规模下至关重要。作者也提示结果会随查询结构、数据规模、硬件和缓存条件而变化。

**「启示」** Sirius 的价值在于把 GPU 执行嵌入 DuckDB 既有 SQL 工作流，让受支持的分析查询无需改写即可加速，并以 CPU 回退兜底。不过其性能结论来自厂商自测且计时口径不完全对等，读者应结合自身硬件与负载，用其公开的基准工具独立验证。
