**「背景」** 此次事件涉及 WebPKI 信任链中的中间 CA：浏览器和操作系统通过根证书信任中间 CA，由后者签发终端实体证书，因此中间 CA 私钥一旦泄露，攻击者可签发被广泛信任的证书。据社区评论转述，涉事 8 个 CA 的私钥强度极弱，其中一把私钥仅为单字节“4”；该说法来自评论者引用的外部帖文，尚未在给定材料中得到独立证实。Go 已发布紧急更新，以 SHA-256 哈希形式屏蔽这 8 把 CA 密钥，但 Mozilla 与 Go 均未公开说明触发原因。

**「对 Go 用户的影响」** Go 团队于 10 月 20 日发布 1.27.3 和 1.26.10 紧急更新，在 crypto/x509 中拒绝经过这些 eMudhra 中间 CA 的证书链。使用受影响证书链的 Go 服务在升级后可能立即出现 TLS 握手失败，需改用其他签发链或评估兼容性。

**「社区讨论」** 有评论者质疑把单字节私钥称为“compromise”是否恰当，认为这更像密钥生成或保管的根本性失误；也有人指出密钥可能曾公开存放在 repository.emsign.com 的证书路径下，但承认自己可能误读，呼吁有资质的人给出可信解释。Mozilla 的 galadran 强调影响分布极不均衡：浏览器厂商已有 OneCRL、CRLite 等规模化吊销工具，而生态其余部分几乎未投资吊销机制。另有评论批评 WebPKI 把精力放在缩短证书有效期等末端限制上，而这类措施并不能阻止本次事件，问题根源在 CA 的密钥策略与执行。还有评论提醒 Go 用户升级到 1.27.3 或 1.26.10。

### [Cloudflare 发布 tsrs：用 Rust 移植 TypeScript 编译器](https://blog.cloudflare.com/typescript-rust-port/) ⭐️ 7.0/10

Cloudflare 博客介绍了 tsrs，这是用 Rust 重写的 TypeScript 编译器移植版本。它采用永不释放的 arena 内存模型，以绕开 Rust 缺少垃圾回收、而 TypeScript 原本依赖 GC 的问题。据社区讨论，该项目的直接动机是让 TypeScript 编译器能在 Cloudflare 仅支持 WASM 的沙箱中运行，因为把 tsc 编译成 Go/WASM 会带上完整的 Go 运行时。TypeScript 团队成员 DanRosenwasser 表示，他们正与维护者合作弄清 tsrs 为何快、哪些优化是安全的，并称目前怀疑速度提升很大一部分并非只来自语言选择。

hackernews · hnisjafx40 · 10月20日 13:18 · [社区讨论](https://news.ycombinator.com/item?id=50165953)

**「背景」** tsrs 是 oxc 项目发布的 Rust 版 TypeScript 7 编译器与语言服务器，目标是作为可直接替换的实现，在保持 100% 一致性的同时降低内存占用并加快类型检查。据社区讨论，TypeScript 团队当初未选择 Rust，部分原因是 Rust 没有垃圾回收，从带 GC 的语言移植往往需要重构数据结构；tsrs 通过永不释放的 arena 为长生命周期对象模拟 GC 来绕开这一限制。

**「对使用者的影响」** 对在大型代码库上使用 TypeScript 的团队而言，这一移植可能提供比现有 tsc 更快的编译路径，但性能结论目前仍属“怀疑”阶段，尚未成为经过独立验证的稳定能力。TypeScript 团队正在评估其中哪些优化可以安全借鉴，这意味着相关收益也可能回流到官方编译器，而非只存在于 tsrs 中。

**「社区讨论」** 评论者 afdbcreid 指出，tsrs 用永不释放的 arena 为长生命周期对象“伪造 GC”，并希望这种做法在 Rust 中是内存安全的。sheepscreek 认为项目初衷并非打造更快的 Rust 编译器，而是获得能在 WASM 沙箱中运行的编译器，速度提升只是附带结果。egonschiele 则对博客中“前沿 AI 模型可在数天内几乎独立完成大规模移植、我写了零行代码”的说法表示不安，担心从精心手写的移植转向完全由 AI 生成的移植。

### [用 cuTile 实现 Mamba-2 前向三内核并优化](https://developer.nvidia.com/blog/accelerating-mamba-2-with-high-performance-forward-pass-kernels-in-nvidia-cuda-tile/) ⭐️ 7.0/10

rss · NVIDIA CUDA Technical Blog · 10月19日 17:00

**「背景」** Mamba-2 兼具循环网络的固定隐状态与注意力的矩阵乘友好性，但训练和预填充若按 token 逐位递推，无法利用 Tensor Core；而并行扫描又需物化巨大隐状态张量，受限于显存带宽。Jane Street 与 NVIDIA 合作，用 Python DSL cuTile 重写前向通路，目标是在保持分块递推数学正确性的同时，把计算压到 Tensor Core 上。

**「方案」** 作者先推导分块跳跃公式：把衰减项取对数后，用块内累积和 G 替代逐位连乘，隐状态更新化为 exp\(G\_last\)·h\_t 加上预乘指数的 B 与 X 的矩阵乘；输出则写成 exp\(G\)·C·h 加带因果掩码的 \(C·Bᵀ\) 项再加 D·x 跳连。据此拆成三个内核：chunk\_cumsum 用 ct.cumsum 在块内累加 a·dt 并乘 log2\(e\) 以便用 exp2；fwd\_pass\_state 在单个网格点内顺序遍历块，用 ct.extract 取末位衰减、ct.mma 推进隐状态，块间并行；compute\_out 把交互矩阵留在寄存器中，分两阶段用 ct.mma 累加 C·Bᵀ 与 C·hᵀ，再用 ct.where 现场生成掩码，避免物化掩码张量。优化包括：为 load/store 标注延迟提示以指导流水线深度；在 Blackwell 上利用 BᵀAᵀ=\(AB\)ᵀ 把融合操作数换到 A 操作数以缓解共享内存压力；将 decay\_cumsum 与 dt 转置为按 token 连续布局以启用 TMA；并把块大小、占用率与上述策略纳入 cuTile 自动搜索。在单张 B300 上对比 Triton 参考实现，内核级加速为 1.14 至 1.82 倍，且随序列长度和状态维度增大而提升；作者明确这仅是内核级数据，端到端训练还取决于反向实现。

**「启示」** 作者的核心论点是：把 Mamba-2 的衰减递推改写为对数空间累积和加掩码矩阵乘，就能让分块前向完全落在 Tensor Core 上，而 cuTile 的瓦片抽象让这类内核在 Python 中即可表达并调优。其收益目前限于内核层面，反向通路与端到端影响仍待后续验证。
